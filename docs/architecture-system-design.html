4) Reader: How It Works

Reader is intentionally separate from Editor. It is optimized for immersive reading + on-demand AI assistance.

  1. Import: user adds files (.pdf .epub .docx .txt .md .html) through file picker/folder picker.
  2. Ingestion API: frontend calls POST /api/v1/analysis/ingest-files; backend extracts text + sections (20MB total/request cap).
  3. Persistence: file blob + metadata are stored in IndexedDB for local library continuity.
  4. Render: format-specific renderer draws content in custom reader shell (no browser-native PDF embed path).
  5. Selection: user selects text and right-clicks to open a context menu (red/green highlight + Ask AI).
  6. AI Explain: with Arrow mode enabled, selected text + local context go to /analysis/explain-selection, then response appears in popup/panel.
AI is deliberate: reader AI runs on explicit text selection only. No automatic full-document AI reading.

5) PDF Pipeline (Crash-Safe Mode)

Current PDF path is optimized to prevent blank/black/SIGILL behavior and keep reading smooth.

Load DocumentPDF.js legacy build runs with safer decode options (useWasm: false, offscreen/image decoder disabled) and worker-source fallback (version-matched CDN worker, then local worker asset).
Windowed DOMOnly a page window around current reading position is mounted (top/bottom spacers emulate full-length scroll).
Queued RenderingPages are rendered in a controlled queue; no uncontrolled burst of parallel canvas rendering.
Memory GuardCanvas size is capped by strict side/pixel limits; off-window pages are released to 0x0 backing stores.
Scroll ThrottleScroll-to-page updates are requestAnimationFrame-throttled to prevent render thrash and noisy persistence writes.
Text LayerText layer enables word/sentence selection for AI explanation and PDF highlight anchoring.
Persist PositionReader saves progress and scroll position continuously for session resume.

6) How AI Understands Reader Selections

When Arrow mode is enabled and the user explicitly asks AI on a selected span:

  1. Reader captures selected text and resolves nearby contextual sentence/paragraph.
  2. Frontend calls POST /api/v1/analysis/explain-selection with selected text + context.
  3. Backend builds strict structured prompt and sends request via LiteLLM to Gemini.
  4. Gemini returns JSON fields: definition, meaning in context, concise explanation, usage examples.
  5. Reader shows response in quick popup or persistent AI panel.
If provider quota is exhausted, backend now returns safe concise errors instead of exposing provider internals.

7) Highlighting Model

Flow Documents (TXT/MD/HTML/DOCX)

Highlights are injected as <mark> spans in rendered HTML and persisted by document key.

EPUB

Highlights are stored as CFI ranges + color and replayed on rendition load.

PDF

Selection client rects are converted to normalized percentages per page and persisted in localStorage (reader:pdf-highlights:*).

Colors

All modes support red/green highlights via the reader right-click context menu.

8) Editor: Live Grammar and Spelling Correction

Editor uses debounced live correction with Gemini, tuned for fast typing feedback.

  1. User types; client tracks cursor and current text chunk.
  2. Debounce waits briefly, then calls /analysis/live-correct.
  3. Backend prompts Gemini for grammar/spelling-only corrections (no unwanted paraphrase).
  4. Response returns corrected text + correction count.
  5. Frontend patches only the targeted chunk and restores cursor location.
  6. Manual rewrite and analysis actions remain available as separate controls.

10) API Key Safety Model

  1. User enters Gemini key in UI settings modal.
  2. Frontend sends key to backend setup endpoint over API call.
  3. Backend validates environment restrictions + local/private source checks + optional setup token + allowed origin.
  4. Key is stored server-side runtime env file and process env; frontend only receives configured status (never key preview).
  5. AI requests are performed server-side; key is never embedded in browser JS bundles.

11) Security and Reliability Checklist

  • CORS: enforce explicit origins through CORS_ORIGINS.
  • Auth secret: change JWT_SECRET from default for any non-dev deployment.
  • Upload guard: reader ingest enforces 20MB total request cap.
  • Provider errors: backend now maps quota/auth failures to safe concise messages.
  • PWA cache: disabled + cleanup component to avoid stale frontend bundles during active iteration.

12) Troubleshooting PDF Issues (Operational Playbook)

If PDF appears blank / black

  1. Rebuild and restart frontend: docker compose up -d --build frontend.
  2. Hard refresh browser (Ctrl+Shift+R).
  3. Check frontend logs for runtime exceptions.
  4. Confirm worker asset is served: curl -I http://localhost:3000/pdf.worker.min.mjs.
  5. Verify file size/page count and retry a smaller PDF for baseline.

If AI explain does not answer

  1. Confirm key status endpoint: /api/v1/settings/gemini-key/status.
  2. Check backend logs for quota/auth messages.
  3. If quota is depleted, add billing credits and retry.
SIGILL is usually a browser process crash. Current design reduces crash risk by disabling wasm/offscreen decode paths, limiting canvas size, and rendering only a moving page window.
